# dsh-mishu 需求清单：用户需要秘书做什么

> 2026-10-21 整理。分电脑上的事和电脑外的事，每件按"能不能做、什么时候做"分批。特别的、不容易实现的放在最后的暂缓清单，下一步再说。设计见 [调研与设计.md](调研与设计.md)。

## 依据

- **秘书的本职**：各种行政助理的岗位说明里，反复出现的是日程管理、出行安排、报销、会后跟进待办、处理往来邮件、筛选来电来信（[AbroadWorks](https://www.abroadworks.com/blog/executive-assistant-responsibilities)、[TravelPerk](https://travelperk.com/guides/administrative-tasks/executive-assistant-responsibilities)、[加州食品农业部的岗位任务表](https://www.cdfa.ca.gov/employment/pdfs/Justification_Page/ExecutiveAssistant_Task.pdf)）。
- **生活琐事（life admin）**：哥伦比亚大学法学教授 Elizabeth Emens 在《Life Admin》（2019）里，把经营生活和家庭所需的秘书式、管理式工作叫 life admin：约医生、交账单、在各种"自助"网站上办事，还有婚礼、生孩子、丧事这类人生大事。这些事无人看见，也没有报酬。
- **人最常忘的是"该做的事"**：日记研究发现，"到时候忘了做某件事"（前瞻记忆失误）是日常最常见的记忆错误（[日内瓦大学的研究](https://archive-ouverte.unige.ch/unige:134320)、[赫特福德大学的日记研究](https://researchprofiles.herts.ac.uk/en/publications/how-frequently-do-you-forget-in-everyday-life-a-diary-study-of-pr/)）。但也有研究发现，没做成的事里只有一成多是因为忘了，更多是当时不方便或不想做（[日内瓦大学的另一项研究](https://archive-ouverte.unige.ch/unige:195352)）。所以**光提醒不够，还要在合适的时候提醒，并且让事情一键就能办**。
- **用户自己设的提醒**：微软分析了 Cortana 六个月的提醒日志，发现绝大多数是按时间设的，而且提醒的触发时间跟设定的时间、任务类型都有规律（[Graus 等，UMAP 2016](https://www.microsoft.com/en-us/research/publication/analyzing-predicting-task-reminders/)）。
- **邮件里的承诺和请求**：微软做过从邮件里自动识别"我周五前发给你"（自己的承诺）和"请你……"（别人的请求）的研究，并用在 Cortana 里。专利里提到，拿不准的时候要先问用户（[WSDM 2019 论文](https://microsoft.com/en-us/research/uploads/prod/2019/01/AzarbonyadWSDM2019.pdf)、[Microsoft Research 博客](https://www.microsoft.com/en-us/research/?p=566577)、[专利 US10361981](https://patents.google.com/patent/US10361981)）。
- **实际用量**：2025 年一项美国调查（993 人）显示，18.6% 的人已经在用 AI 管日程（[Verasight](https://data.verasight.io/ai/at-home-people-mostly-use-ai-for-writing-and-recommendations)）。

## 秘书的三种活

1. **盯着**：替你看各个地方来的消息，查清楚现在的状态。
2. **记着**：到期的、周期性的、答应了别人的、等别人回的，到点提醒你。
3. **办掉**：简单的直接办，复杂的准备好材料，等你拍板。

**手动交代**和自动收消息一样重要。很多事没有任何消息源，比如"护照明年 3 月到期"、"每月 15 号交房租"，只能你说一句、秘书记下。交代必须轻松：在 DSH 里说一句，或者在手机上给推送机器人（飞书、Telegram）发一句话，都行。

## 电脑上的事

| 事 | 例子 | 从哪来 | 秘书怎么做 | 批次 |
|---|---|---|---|---|
| 代码和 CI | PR 等你审、@你、CI 失败、issue 指派给你 | GitHub API | 查当前状态再判断；已解决的自动关闭 | 第一版 |
| 安全和依赖告警 | Dependabot、npm 安全告警、包被弃用 | GitHub API、npm | 汇总成事项，标出严重程度 | 第二批 |
| 待回复的邮件 | 直接发给你、对方等你回 | 邮箱（IMAP） | 列为"待回复"；可以起草回复，不发送 | 第二批 |
| 等别人回复 | 你发的邮件 N 天没人回 | 邮箱已发送文件夹 | 提醒你跟进 | 第二批 |
| 你答应别人的事 | 邮件里写了"周五前发给你" | 邮箱已发送文件夹 | 模型识别承诺，**先问你确认**再记成事项 | 第二批 |
| 订阅邮件和噪音 | 新闻邮件、营销邮件、系统通知 | 邮件头 | 折叠并进摘要；可以一键退订 | 第二批 |
| 飞书 | @我、审批、文档评论、任务、日程 | 飞书开放平台 | 列成事项；审批到期提醒 | 第二批 |
| 日程 | 会议邀请待回应、日程冲突 | 邮件里的 .ics、飞书日程 | 提醒回应；发现冲突就提醒 | 第二批 |
| 域名和证书 | 域名、SSL 证书快到期 | WHOIS、直接连上去查证书 | 主动检查，提前 30/7/1 天提醒 | 第二批 |
| 云服务和 API 额度 | 云服务器续费、API 余额不足、订阅扣款 | 各平台查询接口、账单邮件 | 余额低于阈值或快到期时提醒 | 第三批 |
| 应用上架 | App Store、Google Play 审核结果 | App Store Connect / Play 的 API，或通知邮件 | 审核被拒立刻提醒 | 第三批 |
| 服务器告警 | VPS 宕机、磁盘满 | 监控告警邮件或 webhook | 汇总，紧急的立刻推 | 第三批 |
| 会前准备 | 开会前把相关邮件和文档找出来 | 日程 + 邮件 + 飞书文档 | 会前 15 分钟推一份简报 | 第三批 |

## 电脑外的事

这些事大多没有接口，但很多会**以邮件或短信的形式**出现。所以能不能做，主要看能不能读到邮件和短信，以及你愿不愿意手动交代一句。

| 事 | 例子 | 从哪来 | 秘书怎么做 | 批次 |
|---|---|---|---|---|
| 账单和还款 | 信用卡还款日、花呗、房贷、水电燃气、话费、物业费 | 电子账单邮件、银行短信、手动交代 | 记成带截止日期的事项，提前提醒；**不代付** | 第一版（手动），第二批（邮件），第三批（短信） |
| 周期性的事 | 每月交房租、每年交车险、每年体检 | 手动交代一次 | 按周期自动生成事项，提前提醒 | 第一版 |
| 证件到期 | 身份证、护照、港澳通行证、驾照、签证 | 手动交代 | 提前几个月提醒（办证需要时间） | 第一版 |
| 车 | 车险续保、年检、违章 | 手动交代、保险公司邮件或短信 | 到期前提醒 | 第一版（手动） |
| 出行 | 航班、火车票、酒店、值机 | 订票确认邮件、短信 | 整理成行程；提醒值机和出发时间；航班变动立刻推 | 第二批（邮件），第三批（短信） |
| 快递 | 取件码、驿站快超时了 | 短信、快递公司邮件 | 列出待取件；快超时时提醒 | 第三批（短信） |
| 退货和保修 | 7 天无理由快到期、保修期 | 订单邮件、手动交代 | 期限前提醒 | 第一版（手动），第二批（邮件） |
| 发票和报销 | 电子发票、报销截止 | 邮件附件（PDF/OFD） | 自动收集到一个文件夹；报销截止前提醒 | 第二批 |
| 会员和自动续费 | 视频会员、云盘、App Store 订阅 | 扣款邮件或短信、手动交代 | 续费前提醒，问你还要不要 | 第一版（手动），第二批（邮件） |
| 年度政务 | 个税年度汇算（每年 3 月 1 日到 6 月 30 日）、社保公积金 | 固定日历 + 手动交代 | 按固定日期提醒 | 第一版 |
| 健康 | 体检、复诊、牙医、疫苗、续药 | 手动交代、医院短信 | 按日期或周期提醒 | 第一版（手动） |
| 家人和人情 | 生日、纪念日、节日 | 手动交代、通讯录生日 | 提前几天提醒，留出准备礼物的时间 | 第一版（手动），以后读通讯录 |
| 宠物 | 疫苗、驱虫 | 手动交代 | 按周期提醒 | 第一版 |

## 秘书能直接办的

按[调研与设计.md](调研与设计.md)里的动作分级：

| 级别 | 能办的事 |
|---|---|
| L0 自动 | 归档、合并、关闭事项；收集电子发票到本地文件夹；生成每日摘要；按周期生成事项 |
| L1 确认，之后可以改成自动 | GitHub 通知标已读；邮件标已读、挪进文件夹；把事项加进你的日历 |
| L2 每次一键确认 | 关 fork 的 Actions；重跑 CI；一键退订（RFC 8058）；接受或拒绝会议邀请 |
| L3 只起草 | 回邮件、回消息、续费、付款、退货申请 |

## 暂缓清单：特别的、不容易实现的

| 事 | 难在哪 | 可能的路 |
|---|---|---|
| **微信消息**（家长群、工作群、朋友托付的事） | 没有官方接口；本地数据库是加密的；用非官方方式登录有封号风险 | 暂不碰。先让你把重要的事转发给推送机器人，或者手动交代 |
| **手机短信**（银行、快递、运营商） | 要 iPhone 打开"短信转发"到 Mac，还要给 DSH 开"完全磁盘访问"权限，才能读 `~/Library/Messages/chat.db`；只有 Mac 加 iPhone 能用 | 第三批再做。**验证码短信直接丢掉，不存，也不送模型** |
| **Apple 日历和提醒事项** | 要走系统权限（EventKit）；DSH 是 Electron 应用，调用不方便 | 可以先用 AppleScript 或 Shortcuts 试试；第三批 |
| **淘宝、京东、拼多多的订单和物流** | 没有个人接口；抓网页违反条款，账号也有风险 | 通过邮件或短信间接拿 |
| **银行、支付宝账户直连** | 没有个人接口；要输入金融凭据，违反我们的安全原则 | 不做，只通过账单邮件和短信 |
| **政务网站**（个税、社保、公积金、交管 12123 违章） | 没有接口，要实名登录 | 只做固定日期提醒和手动交代 |
| **医院挂号、学校通知** | 多半在微信或各自的 App 里 | 手动交代 |
| **按位置提醒**（到公司提醒我……） | 需要手机端常驻定位 | 要有手机 App 才能做，暂不做 |
| **电话、语音留言、纸质信件** | 根本进不了电脑 | 你拍照或说一句，秘书记下 |
| **Telegram 个人消息** | 要用 MTProto 登录个人账号，有封号风险 | 不读，Telegram 只作为推送出口 |
| **真正替你办事**（预约、下单、付款、回复） | 都是代表你对外行动，判错的代价高 | 只起草、准备材料，由你执行 |
| **家人共享**（全家的账单、孩子的事） | 多人、多账号、权限和隐私都复杂 | 以后再说 |

## 对排期的影响

- **第一版**：GitHub，加上手动交代和周期事项（2026-10-21 定）。后者几乎不依赖外部接口，却能覆盖大部分电脑外的事，所以表里那些标"第一版（手动）"的事，第一版就能靠你交代一句进来。第一版只能在 DSH 里交代，用手机发给机器人要等推送渠道接上。
- **第二批**里**邮件**最关键：账单、出行、发票、订阅、退货的自动识别都靠它。
